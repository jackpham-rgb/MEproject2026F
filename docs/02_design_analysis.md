# Design Analysis: Concept D (Mirror Flip)

All numbers below are regenerated by `sim/*.py` (outputs go to `sim/out/*.txt`, `*.png`). Values
marked **EST** are datasheet values or hand estimates. They get replaced after the Phase 2 bench
system ID, and then the scripts are rerun.

## 1. Geometry (`sim/flip_geometry.py`)

| Quantity | Value | Why |
|---|---|---|
| Flip axis direction | 45° bisector, horizontal, through the robot origin | 180° about it mirrors START (0, 5) to TARGET (5, 0) |
| Flip axis height *h* | **2.39 in** (= 4.7/2 + 0.04) | Landing bottom z = 2h − 4.7. The 0.04 in raises it so the can hovers 0.08 in (2 mm) at 180° instead of being driven into the table |
| Arm radius (axis → can centre) | **3.536 in** (= 5·sin 45°) | Distance of the can centre from the axis line |
| Axial position of the arm plane | 3.536 in from the origin along the axis | Projection of the can centre onto the axis |
| Max can centre height mid-flip | 5.93 in | Top of the arch |
| Min can clearance mid-flip | +0.06 in | Every point on the can only rises after lift-off; the lowest points are at the start and end |
| Counterweight radius limit | **≤ 1.8 in** to its centre, with the body extending ≤ 0.25 in below that | It swings under the axis at 90°. Lowest point = 2.39 − 1.8 − 0.25 = 0.34 in |

**Final-angle error budget** (lowest point of the can at θ_end = 180° + δ):

| δ | −3° | −2° | −1° | 0 | +0.5° | **+1°** | +2° |
|---|---|---|---|---|---|---|---|
| Lowest point (in) | +0.205 | +0.163 | +0.121 | +0.080 | +0.039 | **−0.002 (contact)** | −0.084 |
| Can tilt at release | 3° | 2° | 1° | 0 | 0.5° | 1° | 2° |

The inverted can tips over at 24° (rim radius 1.05 in **EST**, CG at 2.35 in). So **undershoot is
harmless and overshoot is not**. Design target: **θ_end = 179.5°, with zero overshoot past 180.9°.**
This asymmetric spec is the main reason the flip axis runs closed loop.

**Axis-height build tolerance:** −0.04 in puts the hover gap at 0, so the can gets driven into
the table. +0.10 in gives a 0.28 in drop. **Hold h = 2.39 +0.05/−0.02 in.** Make it adjustable,
e.g. slotted motor-mount holes or a shim under the tower.

## 3. Grip force window (`sim/grip_control.py`)

| Item | Value |
|---|---|
| Peak acceleration along the grip | g + ω²r + αr = 11.65 m/s² |
| Slip limit per finger | F ≥ SF·m·a / (2μ) = 3 × 0.015 × 11.65 / (2 × 0.6) = **0.44 N** (μ = 0.6 silicone/TPU on aluminium **EST**) |
| Dent onset per finger **EST** | ~8 N. Measure it: squeeze scrap cans with the printed jaw on a kitchen scale |
| **Setpoint** | **1.5 N**: 3.4× above slip and 5.3× below dent |

Honest assessment: the window is about 18× wide, so a plain servo with foam pads would probably
hold the can too. The force loop still earns its place. It **confirms a real grip before the flip
starts**, so no can or an FSR fault means no flip. It also makes force independent of where the can
sits in the jaws. And it gives force-vs-time evidence for the report.

## 4. Control design

### Flip axis: position loop with feedforward

The plant, taken at the gearbox output with the electrical lag neglected (L/R ≈ 1 ms, much less
than the 5 ms loop):

```
θ(s)/V(s) = K / (s(τs + 1)),   K = Kt/b = 1.745 rad/s/V,   τ = J/b = 40 ms
```

**Why not Ziegler–Nichols:** this plant is type-1, second order, so its phase approaches −180°
but never crosses it. There is no finite ultimate gain to find. Gains come from **pole placement**
instead: a triple closed-loop pole at −30 rad/s, about 6× below the 200 Hz Nyquist rate.

```
Kd = (3ωnτ − 1)/K = 1.49 V·s/rad    Kp = 3ωn²τ/K = 62 V/rad    Ki = ωn³τ/K = 620 V/(rad·s)
```

`V = V_ff + Kp·e + ∫Ki·e + Kd·(ω_ref − ω_meas)`, where `V_ff = (J·α_ref + b·ω_ref + g·m·r·cos θ_ref + T_c·sgn ω_ref)/Kt`.

Two findings from the simulation shaped the firmware:

1. **The derivative term acts on the error rate (ω_ref − ω), not just −ω.** Textbook
   derivative-on-measurement avoids derivative kick on steps. During a moving trajectory it brakes
   the arm by Kd·ω, about 5.7 V at peak speed. In the first simulation that caused 2.4° of
   tracking lag and a 0.8° overshoot at the end. ω_ref comes from the analytic trajectory, so there
   is still no kick.
2. **Feedforward cuts tracking error 3–4×** (0.79° → 0.22°) and keeps the loop in its linear range.

| Case (full flip) | Max tracking error | Peak angle (limit 180.9°) |
|---|---|---|
| Nominal, FF + PID | 0.22° | 179.54° |
| Nominal, PID only | 0.79° | 179.80° |
| Inertia ±30 % | 0.21 / 0.22° | 179.54 / 179.58° |
| Friction ×2 | 0.32° | 179.57° |
| Counterweight missing | 0.60° | 179.56° |

**Bench-comparison baseline:** 30° step, PID only. Rise (10–90 %) 50 ms, overshoot 6.0 %, 2 %
settling 300 ms, steady-state error −0.08°. Repeat this exact test on the hardware for Part C.

### Grip axis: outer force loop on a position servo

The SG90 already runs its own position loop, so the force loop is a velocity-form PI that trims
the servo command: `ψ += Ki·e·dt + Kp·Δe`. The jaws close at 90°/s until the pads touch
(F > 0.15 N), then the PI takes over. Across 0.5×–2× pad stiffness: 0–1.6 % overshoot, 25–335 ms to
settle, and peak force never above 1.52 N. The servo is driven with `writeMicroseconds` for about
0.18° per step instead of 1°.

**Deliberate change from the original plan:** *no grip encoder.* A hobby servo is already a
position actuator, so an encoder on it adds nothing to a force loop. The Uno also has only two
external-interrupt pins (D2/D3), and both are needed for 4× decoding on the flip encoder.

## 5. Firmware architecture (`firmware/can_flipper/`)

- **Timer2 CTC at 200.3 Hz** raises a flag. `loop()` runs sensing, control and actuation when it
  is set. The ISR does no float math, `analogRead` or `Serial`. Worst-case control path measured in
  the AVR emulator: **1.49 ms of the 5 ms budget, 0 missed ticks**.
- **State machine:** `HOME → IDLE → DETECT → GRIP → FLIP → RELEASE → RETURN → SEAT → DONE`, and
  any state can go to `FAULT`. Every transition waits on a measured condition: a switch closed, the
  force inside its band for 150 ms, or the angle within 0.5° and speed below 0.2 rad/s for 100 ms.
  Timers exist only as fault timeouts.
- **Faults:** homing timeout, no can detected, grip timeout, over-force (> 4 N), jaws closed on
  nothing, can lost mid-flip (F < 0.35 N), tracking error > 10° (stall or encoder failure), settle
  timeout. A fault cuts the motor and opens the jaws.
- **Home stop:** the arm rests by gravity on a hard stop at θ = 0 with a microswitch in it. That
  re-zeros the encoder every cycle.
- **Trajectory computed online** (a quintic costs a few µs). This replaces the lookup table
  exported from Gazebo in the original plan, and it saves flash and removes a tool-chain step.
- **Hardware-free core:** `control.h` and `sequencer.h` don't include `Arduino.h`. The same code
  is tested on the laptop (`firmware/host_test`) and runs on the Uno.

## 7. Changes from the original plan, and why

| Original plan | Now | Reason |
|---|---|---|
| Concept 1 (claw + flip + turntable) pre-selected | Concept D chosen by the matrix | Concept 1 has an unaddressed lift axis (§ Concept A). D does flip + relocate in one motion |
| Rotate axis: open-loop servo | Removed | The 90° move comes from the geometry |
| 2 encoders (flip + grip) | 1 encoder (flip) | Servo is a position actuator; Uno has 2 interrupt pins |
| Ziegler–Nichols or pole placement | Pole placement | Z-N needs a finite ultimate gain, and this plant has none |
| Gazebo + URDF for reachability, trajectory lookup table | Python sweep + online quintic | For a 1-DOF mechanism a direct geometric sweep is a more thorough check and much faster. Gazebo stays optional |
| Control law inside the timer ISR | ISR sets a flag, `loop()` computes | Keeps `analogRead`/`Serial` out of interrupt context; timing is still deterministic (0 overruns) |
